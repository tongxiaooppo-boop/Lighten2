## 1. 產品概述與目標

- **產品名稱**：消滅胖子 (Defeat Obesity)
- **產品定位**：本產品為「熱量追蹤 + 食譜推薦」一體化工具，而非純食譜規劃工具。系統會根據使用者的目標與實際攝取記錄動態調整後續建議（詳見第 7 節）。
- **核心目標**：結合熱門飲食追蹤 App（如 MyFitnessPal、FatSecret）的核心邏輯、健身營養學（TDEE / 巨量營養素 / 膳食纖維）及台灣在地飲食情境，依據使用者的身體數據、動態消耗與可用備餐時間，精準計算熱量與四大營養素缺口，自動生成個人化的「今日與未來一週食譜推薦」。
- **關鍵設計原則（延續 v2.0）**：使用者多為上班族，平日通勤與工時擠壓了備餐時間。系統必須預設「使用者平日沒有太多時間下廚」，並優先推薦免烹調、低烹調或可外食/超商替代的選項。
- **關鍵設計原則（本次新增）**：台灣人不可能餐餐都吃健身餐。系統必須正視「熱門在地食物 + 偶爾大餐」是正常且必要的生活型態，透過「彈性額度 + 運動等效換算」取代「一味禁止」，才能讓使用者長期願意使用（詳見第 6 節）。

## 2. 使用者數據輸入層 (User Input Layer)

### 2.1 基礎生理數據 (Basic Profile)

- 年齡 (Age)：整數
- 性別 (Gender)：男 / 女
- 身高 (Height)：cm
- 體重 (Weight)：kg
- 體脂率 (Body Fat %)：選填。若未填寫，系統預設採用體重與 BMI 推估公式進行估算（如男士預設 20%、女士預設 28%，或採用 Deurenberg 公式推導）。

### 2.2 動態消耗數據 (Dynamic Expenditure)

- 活動量估算方式（二擇一，避免重複計算）：
  - 方式 A：日常活動等級（久坐 / 輕度活動 / 中度活動 / 高度活動），採對應 PAL 係數。
  - 方式 B：每日步數（自動換算為 NEAT 消耗）。
- 當天特殊活動 (Special Activities)：運動項目（爬山、健走、羽毛球、慢跑、重訓、游泳等）、時長（分鐘）、強度（低/中/高）。

### 2.3 飲食限制與過敏原 (Dietary Restrictions & Allergens)

- 飲食型態：一般 / 素食（蛋奶素、全素）/ 低碳 / 無特殊限制。
- 過敏原/不耐：甲殼類、蛋、乳製品、堅果、麩質、其他（自訂文字欄位）。
- 推薦引擎在匹配食譜前，須先以此欄位過濾掉不符合的品項。

### 2.4 備餐時間與情境

- 平日可用備餐時間：幾乎無 / 5 分鐘內 / 15 分鐘內 / 30 分鐘以上。
- 假日可用備餐時間：同上分級。
- 此欄位直接影響第 5 節「未來一週食譜推薦」的品項篩選權重。

### 2.5 目標模式 (Goal Mode)

- 減脂 (Cut) / 維持 (Maintain) / 增肌 (Bulk)

## 3. 核心計算引擎 (Nutritional Engine)

1. **BMR (基礎代謝率)**：採用 Mifflin-St Jeor 公式計算。
   - 男 = 10×體重 + 6.25×身高 − 5×年齡 + 5
   - 女 = 10×體重 + 6.25×身高 − 5×年齡 − 161
2. **TDEE (每日總熱量消耗)**：BMR × 活動係數（久坐 1.2／輕量 1.375／中度 1.55／高度 1.725）+ 特殊活動消耗卡路里 (METs 算式)。
3. **目標熱量 (Target Calories)**：

   | 模式 | 熱量調整 | 說明 |
   |---|---|---|
   | 減脂 | TDEE × 0.8 | 約 20% 赤字 |
   | 維持 | TDEE × 1.0 | 熱量打平 |
   | 增肌 | TDEE × 1.1 | 約 10% 盈餘 |

4. **熱量安全下限保護機制**：女性 < 1,200 kcal 或男性 < 1,500 kcal 時，系統自動上調至門檻值並提示使用者諮詢專業人士。此保護機制優先於減脂模式的固定赤字比例。
5. **巨量營養素分配 (Macros)**：
   - 蛋白質 (Protein)：每公斤體重 1.6g–2.0g（增肌取上限，維持取中間值）。
   - 脂肪 (Fat)：總熱量的 20%–25%。
   - 碳水化合物 (Carbs)：剩餘熱量由碳水補足。
6. **膳食纖維目標 (Dietary Fiber Target)（本次新增）**：
   - 預設每日 30g，可調整範圍 25–35g（參考衛福部建議及營養師 Excel 工具規格）。
   - 膳食纖維**不列入**三大營養素的熱量計算，獨立顯示與加總。
   - 選用顯示：**淨碳水 (Net Carbs) = 總碳水 − 膳食纖維**，供低碳飲食使用者參考。
   - 三餐纖維目標依第 5.1 節相同比例（早25%/午35%/晚30%/宵夜10%）分配。

## 5. 推薦引擎邏輯與標籤匹配 (Recommendation Logic)

### 5.1 熱量與 Macro 配額拆解

早餐 25% / 午餐 35% / 晚餐 30% / 宵夜與運動補充 10%（膳食纖維目標依相同比例分配）。

### 5.2 宵夜/運動補充配額觸發條件（OR 邏輯）

滿足以下任一條件即開啟：(1) 當天有高強度運動（如爬山、羽球 90 分鐘以上），或 (2) 晚餐後剩餘熱量額度 < 300 kcal 且使用者登記宵夜需求。皆不成立則不主動推薦宵夜。

### 5.3 備餐時間優先於「工作日/假日」二分法

系統依使用者當日設定的「可用備餐時間」動態篩選食譜分級（🟢/🟡/🔴），星期僅作預設參考值，可隨時覆寫。

### 5.4 食物標籤與自動匹配機制

（內容同 v2.0，見附錄 C。）

### 5.5 份量縮放邏輯

縮放係數 = 該餐熱量配額 ÷ 食譜基準熱量，限制在 0.7–1.3 倍之間；超出範圍改為推薦替換品項。蛋、水果等不可分割食材以整數呈現，克數類食材可線性縮放。

## 6. 彈性台式餐與大餐制度 (Flexible Taiwanese-Style & Feast Meal Allowance)（本次新增核心功能）

### 6.1 設計理念

台灣人的日常飲食本來就以外食、聚餐、應酬為主，系統若強迫使用者每餐都吃改造版健康餐，長期黏著度會很低。因此本次新增「彈性額度」機制：允許使用者在額度內選擇「未經改造的台式熱門排行榜原版」與「大餐」，並用**運動等效換算**取代單純的禁止或罪惡感提示。呈現語氣採「資訊對照」，不使用「代價」「處罰」「贖罪」等字眼，避免誘發把運動當作補償手段的不健康心態。

### 6.2 各目標模式的彈性額度設計

| 目標模式 | 每週彈性額度（預設，可調整） | 系統行為 |
|---|---|---|
| 減脂 (Cut) | 5 餐台式熱門原版（建議分配：午餐×3、晚餐×2，使用者可自訂落在哪幾天）+ 1 餐大餐 | 觸發第 6.3 節熱量結餘計算；若使用者 3 天內未完成建議運動，系統自動小幅調降後續幾餐配額分攤補償（每餐約 −5%~−8%），並提供「以運動補償」或「以飲食微調補償」兩種模式供選擇 |
| 維持 (Maintain) | 7 餐台式熱門原版 + 1–2 餐大餐（因不需熱量赤字，額度預設較寬鬆） | 僅顯示熱量結餘與運動等效資訊，不觸發配額調降；仍持續透過飲食紀錄追蹤整體熱量是否長期偏移 |
| 增肌 (Bulk) | 同維持期額度 | 因本身有 10% 熱量盈餘，台式/大餐對整體熱量目標衝擊較小；系統改為著重提示**蛋白質缺口**（多數台式熱門餐蛋白質偏低），建議於下一餐或當日稍後以高蛋白食物補足 |

其餘未列入彈性額度的餐次（所有早餐、剩餘午晚餐、宵夜），仍依第 4–5 節健康食譜或改造建議邏輯運作。

### 6.3 熱量結餘 × 運動等效換算引擎

使用者選擇「台式原版」或「大餐」時，系統即時計算：

```
結餘熱量 = 該餐實際攝取熱量 − 系統原本改造建議的熱量配額
```

再依 METs 公式反推抵銷結餘熱量所需的運動時間，提供 3–4 種常見活動供參考：

```
所需分鐘數 = 結餘熱量 ÷ (METs × 3.5 × 體重(kg) / 200)
```

呈現範例（資訊對照語氣，非強制指令）：

> 「這餐比原建議多出約 320 kcal，大約相當於：快走 58 分鐘 / 慢跑 33 分鐘 / 游泳 40 分鐘 / 騎自行車 45 分鐘。」

常用活動 METs 參考值（供系統內建，可隨資料更新調整）：

| 活動 | METs |
|---|---|
| 快走 (5–6 km/h) | 3.8 |
| 健走（含坡度） | 4.5 |
| 慢跑 (8 km/h) | 8.0 |
| 騎自行車（中速） | 7.0 |
| 游泳（自由式，中等強度） | 8.3 |
| 羽毛球（一般對打） | 5.5 |
| 爬山 | 6.5 |
| 重訓（一般強度） | 5.0 |

### 6.4 範例試算（比照營養師 Excel 工具驗收標準：175cm、70kg、30歲、男性、中度活動、減脂模式；數值採 4.3.1 節實際查得資料）

- TDEE ≈ 2,554 kcal，減脂目標 ≈ 2,043 kcal/日。
- 午餐健康配額 ≈ 715 kcal（35%）。選擇排骨便當（4.3節估算範圍880–1,055 kcal，取代表值950）→ 結餘 +235 kcal → 約等同快走 43 分鐘 / 慢跑 24 分鐘。
- 晚餐健康配額 ≈ 613 kcal（30%）。選擇個人小火鍋含飯（估算範圍700–950 kcal，取代表值900）→ 結餘 +287 kcal → 約等同快走 52 分鐘 / 慢跑 29 分鐘 / 游泳 35 分鐘。
- 大餐（如熱炒聚餐數道＋啤酒，依高敏敏「熱炒店熱量圖鑑」估算約 1,800–2,000 kcal，取代表值1,900，較平均一餐配額 680 kcal 多出約 1,220 kcal）→ 約等同慢跑 125 分鐘，系統會建議分 2–3 天完成，而非要求單次補完。

> 代表值取自 4.3 節整份熱量估算範圍的中位數或常見值，實際結果由系統依當日食物資料庫熱量與使用者實際體重、活動數據動態計算；不同店家與份量仍會造成落差，UI 應標註「僅供估算參考」。

### 6.5 與現有食物資料庫整合

- 第 4.3 節台式熱門排行榜品項需比照第 6.4 節，逐一建立「整份熱量估算值」（含 ±15% 誤差標註），作為 6.3 節計算的資料基礎。
- 第 4.4 節原型食材資料庫可用於將複合式台式餐點（如排骨便當＝白飯＋炸排骨＋滷蛋＋青菜）拆解估算，提升估算準確度。

## 7. 輸出產物 (Deliverables)

1. **今日飲食建議**：依當日運動數據、備餐時間設定與彈性額度使用狀況，動態調升熱量配額、篩選食譜難度，輸出三餐與運動前後補充之具體組合、份量縮放結果、總 Macro 統計（含膳食纖維）。
2. **未來一週食譜推薦**：依每日備餐時間分級輸出；同時標示本週彈性額度使用進度（例如「本週台式餐 2/5、大餐 0/1」），並顯示第 6 節之運動補償建議清單。
3. **採買清單**：需自炊食譜之食材依名稱＋單位正規化加總；免烹調/超商替代品項另列「本週建議採購的即食品」子清單；台式/大餐選項不列入採買清單。
4. **實際攝取記錄**：使用者可標記「已依建議食用」或自行輸入實際攝取內容（含選擇台式原版/大餐時），系統依落差動態調整後續建議，並更新第 6 節彈性額度剩餘量。

## 9. 待確認事項 (Open Questions)

1. 熱量安全下限的門檻值（1,200 / 1,500 kcal）是否需依年齡、身高再細分？
2. 份量縮放上下限（0.7–1.3 倍）是否符合實際食譜可微調範圍，需與營養師確認。
3. 超商替代方案的營養資料需對應實際廠牌與品項，建議建立獨立「超商即食品資料庫」並定期更新。
4. 實際攝取記錄的輸入方式（拍照辨識 / 文字搜尋 / 語音）尚待決定。
5. **（本次新增）** 現有健康健身食譜卡尚未包含膳食纖維數值，需依 4.4 節原型食材資料庫逐一核算，未使用原型食材的複合材料（如起司、優格、藜麥、鯛魚、蝦仁等）需另外取得可靠來源數據，避免提供未經查證的營養標示。
6. **（v3.1 已補上初步數據，仍待驗證）** 4.3 節的整份熱量估算已改為依公開營養師/機構資料彙整之區間值，但「家常菜」「鐵板燒」「串燒/燒烤」三項缺乏權威來源、變異度高，建議後續以實測秤重方式建立更可靠數據，或開放使用者手動輸入店家標示熱量校正。
7. **（本次新增）** 第 6.2 節「3 天內未完成運動則自動調降配額」的具體天數與調降幅度需經使用者測試驗證，避免造成使用者因短期未達標而過度緊繃。
8. **（本次新增）** METs 值會因個人體能與實際強度有落差，建議於系統中註明「僅供估算參考」，並允許使用者依個人穿戴裝置實測數據校正。
