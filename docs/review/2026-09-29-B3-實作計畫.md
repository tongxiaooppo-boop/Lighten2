## 3. 程式結構

### 3.1 檔案格式

```js
{
  format: "lighten2-backup",
  schema_version: 1,
  exported_at: "2026-09-29T12:34:56.789Z",
  app_version: "20260929-183757",        // new URL(import.meta.url).searchParams.get("v")；只供人看〔3-2〕
  manifest: { user_profile: 1, settings: 2, recipe_feedback: 40, daily_log: 12, weight_log: 3, exercise_log: 2, custom_foods: 1 },
  sections: {
    system: {
      user_profile: { ... } | null,
      settings: [ { id: "tdee_state", value: {...} }, { id: "picker_last_meal_type", value: {...} } ], // id 不含前綴
      recipe_feedback: [ { id: "<組合 id>", value: { recipe_template_id, rating, shown_count, last_shown_date } } ],
    },
    logs: { daily_log: [...], weight_log: [...], exercise_log: [...] },
    custom_foods: [...],
  },
}
```

- 各陣列依 id（weight_log 依 log_date）排序，同一份資料匯出兩次內容相同。縮排 2 格。
- `manifest` 由 db.js 的 `exportAllData` 自己算（跟 `summarizeBackup` 同一處，C2）〔N3〕；`validateBackup` 要求它跟 `sections` 的實際筆數一致，否則拒絕（檔案被截斷或改過）。
- `exported_at`、`app_version` 由 ui 補；`validateBackup` 對兩者**放寬**：有的話 `exported_at` 必須是可解析的日期字串、`app_version` 必須是字串，缺也放行（smoke 直接拿 `exportAllData()` 的輸出匯入）〔N3〕。

## 6. 使用者決定

- **A. 還原前要不要強制先匯出目前資料？**〔審核建議選項 2〕
  - 選項 1：按鈕可按可不按。
  - 選項 2（建議）：目前資料不是空的時，要先按過「先匯出目前的資料」或勾「目前的資料不需要保留」，「還原」才能按。理由：取代沒有復原，iOS 上下載失敗不一定看得出來。
  - 計畫先照選項 2 實作；使用者要選項 1 只是拿掉一個條件。
- **B. 舊格式紀錄怎麼處理？**
  - 選項 1：`migrateBackup` 補機械上安全的缺欄（`totals` 缺鈉／飽和脂肪補 null、`partial` 補 []，符合 B5.1），其他照擋。
  - 選項 2：預覽列出不合法的筆數，使用者按「略過這 N 筆後還原」。
  - 選項 3：全部擋下。
  - 計畫先做「匯出自我驗證」並照選項 3 擋下；使用者手機跑短清單第 19 項後依實際結果再決定（lighten2 的網頁 09-29 才開，手機資料可能都在驗證器變嚴之後寫入，那就不需要處理）。
