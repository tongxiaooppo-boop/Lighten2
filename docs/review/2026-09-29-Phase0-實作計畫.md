# Phase 0 實作計畫（2026-09-29，送獨立審核前的草案）

依據：PRD 第 2、3、4、6、7（Phase 0 列）、9、10 節；decisions #1–#8、#13、#20、#25、#27、#28、#33、#34；round2 第 2 節的 Phase 0 規格（[紀錄](../../collab/opus-review-log/2026-09-28-prd-2.0-architecture-round2.md)）。
round2 寫在 −1a／−1b 之前，用的是 v1 的名稱（`source_type`、`manual_combo`、`feast.js`、`window.tierRank`、交給 Cline）。這份計畫把它**對照現在的程式重寫**，並併入 −1b 手機實測與 `tools/mobile-walkthrough.mjs` 截圖發現的問題（`docs/日後討論.md`）。

## 1. 現況（−1b 驗收後）

- 「自己選」是 v1 的單一 modal：`現成品項｜自己煮` radio（`js/ui/manual-picker.js` 408 行、`js/ui/item-picker.js`）。
- 現成品項模式排除整份餐盒與台式非飲料（`excludeWholeMeals`），飲料跟食物混在同一格網，被擋品項統一排最後，底部有「可以考慮加：…」（`suggestFillers`）。
- 自己煮：單一蛋白質、單一蔬菜；飲料放在自己煮模式裡（`compose.drink`）；用油與調味用預設值（`composeImplicit`），畫面沒有選項。
- 已經有的：MealContent 與 `daily_log` 新格式（含 `meal_type`、`implicit`、`estimate` 元件的驗證）、`MANUAL_ROLE_MAX`、`manualSelectionProblem`／`canAddManualItem`、`ESTIMATE_SIZE_KCAL`、`validateCustomFood`／`addCustomFood`、`getSetting`／`setSetting`、`tierRank`、check-arch C4.15（`picker_last_meal_type` 只給自己選）。
- 沒有的：`COMPOSE_MAX`、多選自煮的計算、型態分頁、預設分頁解析、快煮/開伙子切換、用油/調味選項、估算卡片、快速新增表單。

## 2. 範圍

**做**（PRD Phase 0 列）：
1. modal 改成三個型態分頁：超商｜外食｜自煮（`<button role="tab" aria-selected>`），取代 radio。
2. 預設分頁：`meal_prefs[slot]` → `picker_last_meal_type[slot]` → `convenience`（PRD 第 4 節；Phase 0 沒有 plan）。`cook_quick`／`cook_full` 對應自煮分頁＋子切換。
3. 商品分頁（超商、外食）：
   - 分組：超商分頁＝`convenience_items` 裡 `channel: convenience` 且不是飲料；外食分頁＝`taiwan_items` 非飲料＋`convenience_items` 裡 `channel: delivery`（連鎖健康餐盒、宅配健身餐）。**整份餐盒、便當都列出**（刪 `excludeWholeMeals`／`WHOLE_MEAL_CATEGORIES`）。
   - 組內照資料原始順序，不按熱量排（PRD 6.1）。依 `category` 分組顯示組名。
   - 被擋的品項：**在各組內排到最後**、灰階、寫原因（round2；取代現在「全部擠到清單最底」的做法，−1b 實測使用者以為沒反應）。
   - 「我的品項」放在該分頁最後一組（依 `channel`），下方「＋新增到我的超商/外食品項」。
4. 飲料抽成三分頁共用的獨立步驟：放在分頁內容下方、摘要上方，「加飲料（選填）」，第一個選項「不加」，單選。切換分頁不清掉。只顯示熱量，不做糖量警告、不預設無糖（PRD 6.1）。
5. 自煮分頁：
   - 子切換「快煮（簡單料理）｜開伙」，值就是這餐的 `meal_type`（decisions #34），不從食材反推。快煮下 `tierRank(prep_tier) > 1` 的烹調法／食材灰階（跟推薦 `cook_quick` 同一條規則，搬到 engine 共用）；已選的保持可取消，送出時擋下並提示。
   - 蛋白質最多 2、蔬菜最多 3（`COMPOSE_MAX`，放 `core/config.js`），達上限提示。主食、醬料、烹調法單選。
   - 縮放：主要槽位＝有主食槽就是主食，否則蛋白質；**蛋白質主要槽位只在選了 1 個蛋白質時有滑桿**（2 個蛋白質固定 1 份各一），蔬菜不縮放（round2 2.10 第 7 點）。
   - 用油選項：「預設（N g，依用油習慣）｜不用油｜1 茶匙（5g）｜2 茶匙（10g）」；調味：「清淡｜一般」（依 decisions #28 預設）。「不加調味」待 C3（日後討論），這次不做。選的值寫進 `implicit`（已是 MealContent 的一部分）。
   - 步驟編號只數目前看得到的步驟（截圖發現「1. 選餐型」後直接跳「4.」）。
6. 外食分頁最上方「找不到？直接估算」：名稱（選填，預設「外食估算」）＋S/M/L（400/700/1200 kcal，`ESTIMATE_SIZE_KCAL`）→ `estimate` 元件，只存在這一餐。蛋白質等未知是 null（C4.5）。文案延續「有聚餐？先記下來，其他餐會自動調整」（PRD 9 節提醒）。
7. 「我的品項」快速新增（超商/外食分頁）：名稱、熱量、角色晶片（早午晚預設主餐、下午茶/宵夜預設點心）、過敏原（未確認〔預設〕／確認不含／含：勾選）；`channel` 取目前分頁；`valid_slots` 依角色推預設且一定含目前時段；其餘營養欄位 null；`vegan`/`lacto_ovo` false。走 `validateCustomFood`（章程 B8），存完直接選中。PRD 10.1 其他欄位（`archived`、`copied_from`、`updated_at`）先寫預設值，管理畫面在 B-1。
8. `picker_last_meal_type`：送出成功（`addDailyLog` 成功）後才寫 `settings`，寫失敗只記 console；每時段一個值直接覆蓋；推薦、統計、hero 不讀（check-arch C4.15 已有）。
9. 送出：
   - 規則沿用 `manualSelectionProblem`（只限各角色數量，不要求主餐，decisions #20；**推翻 round2「早午晚至少 1 個 main」**）。
   - 商品分頁：目前分頁的選取＋飲料 → `contentFromProducts`，`meal_type` 就是分頁（取代 −1a 過渡的「看第一個主餐的來源」、我的品項用自己的 `channel`，decisions #34）。
   - 自煮分頁：`contentFromCompose`（改成接受陣列）＋飲料＋`implicit`，`meal_type` 取子切換。
   - 估算：`estimate` 元件，`meal_type: delivery`。估算可以跟外食分頁的商品、飲料一起送（同一餐）。
   - 每個分頁各自記住選了什麼，切換不清空；送出只算目前分頁＋飲料。
10. 刪除 `suggestFillers`（「可以考慮加：…」）：round2 判定它不管型態、是推銷式提示。缺口文字（「蛋白質缺口約 N g」）保留。

**不做**：`meal_plan`、人口數、我的組合（平行工作線 C）、我的品項的管理畫面／隱藏／複製（B-1）、我的品項進推薦（B-2）、不加調味選項（待 C3）。

## 3. 程式結構

- **engine（純函式，check-engine 測）**：
  - `engine/picker.js`（新）：`resolveDefaultMealType(slot, mealPrefs, lastPicked)`、`partitionByMealType(items)`（回傳 `{ convenience, delivery, drinks }`，我的品項依 `channel` 進對應分頁）、`groupByCategory(items)`（保留原順序、被擋的排組內最後）、`quickTierBlocked(item)`、`quickAddDefaults(slot, role, channel)`。
  - `engine/meal-content.js`：`composeTotals`／`contentFromCompose`／`composeImplicit` 改吃 `protein: []`、`vegetable: []`；主要槽位規則；使用者覆寫的用油克數與調味程度；`contentFromEstimate(size, name)`；`COMPOSE_MAX` 的 `composeAxisProblem`。推薦候選池仍是單一蛋白質/蔬菜（不動推薦演算法），只有「自己選」多選。
  - `core/config.js`：`COMPOSE_MAX = { protein: 2, vegetable: 3 }`、`OIL_OPTIONS_G = [0, 5, 10]`。
- **ui**：`js/ui/meal-picker/`（新資料夾，取代 `manual-picker.js`、`item-picker.js`）：`index.js`（開關 modal、狀態、分頁列、送出）、`product-tab.js`、`cook-tab.js`、`drink-step.js`、`estimate-card.js`、`quick-add.js`。ui 不自己加總（C4.11），摘要一律呼叫 engine。
- **index.html／css**：modal 結構照 round2 2.3；分頁列樣式；modal 的摘要＋按鈕列固定在底部（sticky），內容區自己捲動——修掉截圖看到的「剛打開底部溢出、按鈕要捲才看得到」；可點的元素高度 ≥ 44px（晶片、選項、滑桿觸控範圍）。
- **資料**：不改 `data/*.json`。

## 4. 驗收（取代 round2 2.10，對照現在的程式）

1. modal 沒有 radio，是三個分頁；自煮分頁有快煮/開伙子切換。
2. 預設分頁依 PRD 第 4 節；只點分頁再取消，不改變下次停在哪頁；送出後才更新（check-engine 測解析函式、mobile-walkthrough 測流程）。
3. 超商分頁有餐盒、沙拉，沒有飲料；外食分頁有便當、麵、麥當勞、連鎖健康餐盒，沒有飲料；依分類分組，組內原始順序；被擋的在組內最後、灰階有原因。
4. 飲料步驟三分頁都有，切換分頁保留已選，可選「不加」。
5. 只選一杯飲料可以送出（任何時段，decisions #20）；同角色第二個被擋並提示。
6. 快煮高 tier 灰階；已選可取消；送出時擋下並提示。
7. 蛋白質最多 2／蔬菜最多 3，達上限提示；單一蛋白質才有蛋白質滑桿；蔬菜不縮放；多選的營養合計與 MealContent 元件正確（check-engine）。
8. 用油／調味選項改了，摘要與寫進 `daily_log` 的 `implicit`、`totals` 跟著變。
9. 估算卡片：S/M/L 寫成 `estimate` 元件，未知營養是 null、鈉「無資料」。
10. 快速新增：通過 `validateCustomFood`，新增完在目前分頁、目前時段看得到並已選中；過敏原未確認的在有設過敏原時被擋。
11. `daily_log` 的 `meal_type` 等於送出時的分頁／子切換；推薦卡片的「記錄這餐」不變（diff-recs）。
12. `picker_last_meal_type` 只在送出成功後寫；grep 只出現在 db 與選擇器（check-arch C4.15）。
13. grep 清乾淨：`excludeWholeMeals`、`WHOLE_MEAL_CATEGORIES`、`manual-picker-mode`、`syncModeRadios`、`suggestFillers`、`compose.drink`。
14. 選擇器不讀 `exercise_log`（C4.12）。
15. check-data／check-engine／check-arch／diff-recs 全過（picker 快照改成三分頁的新情境，逐項附差異報告）；smoke-browser 全過；**mobile-walkthrough 第 3 節改寫並全過、截圖逐張看過**；使用者跑短清單。

## 6. 要審核確認的問題

1. 推翻 round2「早午晚餐至少 1 個 main 才能送出」，改用 decisions #20（只限角色數量）——兩者衝突時以較新的 #20 為準，對嗎？
2. **手動記錄的主餐上限 1 個**：超商常見「雞胸肉＋地瓜」（`conv_bx04` 蛋白質單品、`conv_bx05` 原型主食都是 `main`），現在不能一起記。要不要把手動的 `main` 上限放寬到 2，或把這兩類改角色？（資料角色是推薦組合規則的一部分，改角色會動推薦；放寬手動上限只影響記錄。）
3. 刪除 `suggestFillers`（round2 的判斷）是否仍成立？
4. 被擋品項排「組內最後」而不是整個清單最後，夠不夠讓人看出「被擋了」？要不要在組名旁標「N 項因設定不顯示」之類的中性文字？
5. 自煮 2 個蛋白質時固定各 1 份、不給滑桿：熱量可能遠超時段配額（例：雞腿＋鮭魚）。摘要已會顯示「這組合約 N kcal，配額約 M kcal，仍可送出」，這樣夠嗎？
6. 用油選項「預設／不用油／1 茶匙／2 茶匙」：decisions #13 只寫 1 或 2 茶匙；加「不用油」是否合理（氣炸、水煮本來就 0）？
7. 估算卡片的 `meal_type` 固定 `delivery`（PRD 8 節「外食＝別人做的」）；它能跟外食商品同一餐送出嗎？
8. `engine/picker.js` 放 engine 是否恰當（它是選擇器規則但不碰 DOM，要被 check-engine 測）？
9. 其他漏掉的、跟章程衝突的。
