# 手機實機腳本

章程 C5.2、C6.5：畫面流程改到的時候，跑受影響的段落；每個 Phase 驗收時跑完整版。

桌機上的同一套流程已由 `node tools/smoke-browser.mjs` 自動跑過（無頭 Edge/Chrome，會檢查 console 錯誤與資料庫格式）。這份腳本只管自動測試測不到的部分：手機上的觸控、版面、實際網址與快取。

每一步寫「做什麼 → 應該看到什麼」。發現問題時，把重現步驟補在對應段落下面。

## 0. 開啟

1. 用手機開正式網址 → 頁面正常顯示，上方分頁只有「基本資料／今日建議／本週總覽／運動紀錄／採買清單」五個（沒有美饗日曆）。
2. 部署新版本後重新打開（不手動清快取）→ 看到的是新版本（import map 版本字串，章程 C1.6）。

## 1. 基本資料

1. 填年齡、性別、身高、體重、活動量、目標模式，按「計算」→ 計算結果出現；體重趨勢校正卡片顯示「公式目標／校正值／目前每日目標」。
2. 過敏原勾選框、「今日建議時段與來源」下拉都點得到，按鈕高度夠手指點（≥ 44px）。
3. 「今日體重回填」送出 → 顯示「已記錄 日期 體重 kg」。
4. 過敏原勾選框有 10 個（含「軟體動物」「花生」）；飲食型態下拉沒有「低碳」，另有「低碳」勾選框與「家裡用油習慣：一般／少油」下拉；勾選、改選後按「計算」，重新整理再回來，設定還在（−1b）。

## 2. 今日建議

1. 切到今日建議 → 上方彙總卡顯示接下來幾餐的建議熱量；各時段有推薦卡片；關閉的時段顯示「已設定不需要這個時段的建議」。
2. 按「記錄這餐」→ 該時段變成「已記錄：…（約 N kcal）」＋「撤銷」；彙總卡的熱量與蛋白質跟著變。
3. 按「撤銷」→ 該時段回到推薦卡片。
4. 按「倒讚」→ 該時段換一個推薦。
5. 按「順便不要」的晶片 → 該食材/品項從推薦中消失，也出現在基本資料的「不吃的食材」。
6. 記下推薦卡片上的組合，切到別的分頁再切回來 → 推薦跟剛才一樣，沒有整批換掉（−1b，decisions #39）。
7. 按「記錄這餐」記早餐 → 午餐、晚餐的推薦不變，而且不會出現剛才早餐吃的同一個品項。
8. 自煮的推薦卡片（煎、炒）的基準熱量後面有「含用油約 Ng」；基本資料改成「少油」後，數字減半。
9. 彙總卡展開營養明細 → 有「鈉 約 N mg（參考 2400 mg）　飽和脂肪 約 N g」（或「無資料」「部分品項無資料」），沒有顏色或警告。

## 3. 自己選

1. 在推薦卡片按「自己選」→ 彈出視窗，預設「現成品項」，卡片可以捲動、點選。
2. 選一個主餐 → 下方摘要「已選 1 件 · 約 N kcal … · 鈉 約 N mg」；同一角色選第二個時出現提示。
2a. 早餐只選一杯飲料（例：拿鐵）→ 「記下這餐」可以按，記得下來（手動記錄不要求主餐，−1b）。
2b. 基本資料勾了任何過敏原時，便當、餐盒、沙拉這類複合料理灰掉並顯示「成分未確認」。
3. 按「記下這餐」→ 視窗關閉，該時段變成已記錄。
4. 切到「自己煮」→ 依序選餐型、蛋白質、主食、烹調法，份量滑桿可以拖 → 摘要跟著變；按「記下這餐」→ 該時段變成已記錄。
5. 選「免開火」再選需要加熱的食材 → 該食材灰掉「這個食材需要加熱」。
6. 點視窗外的灰色區域或按「取消」→ 視窗關閉，沒有記錄。

## 4. 本週總覽、運動紀錄

1. 本週總覽 → 列出本週每一天的熱量；沒有完整記錄的日子時顯示說明文字。
2. 運動紀錄 → 選項目、填分鐘、送出 → 歷史紀錄出現；本週活動量文字更新；運動分頁不出現任何飲食熱量。
