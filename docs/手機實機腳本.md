# 手機實機腳本

章程 C5.2、C6.5。分兩層：

1. **實作者先跑自動版**：`node tools/mobile-walkthrough.mjs` 模擬手機（390×844、觸控），照下面第 0–4 節逐步操作與檢查（步驟編號對應程式裡的訊息，例：「2-5」＝第 2 節第 5 步），每一步截圖；另外自動檢查畫面不能左右溢出、不能出現時段插畫以外的圖，按鈕不到 44px 列成警告。**實作者要逐張看過截圖**，問題修好才交給使用者。
2. **使用者只跑下面的「使用者短清單」**：自動測不到的部分。

每一步寫「做什麼 → 應該看到什麼」。發現問題時，把重現步驟補在對應段落下面，能自動化的也加進 `tools/mobile-walkthrough.mjs`。

## 使用者短清單（約 5 分鐘）

1. 用手機開 https://tongxiaooppo-boop.github.io/Lighten2/ ，重新整理一次 → 是這次的新版（實作者會告訴你這次看哪裡辨認，例如某個新出現的字）。推送後 10 分鐘內看到舊版是 GitHub Pages 的暫存，不算問題。
2. 隨手用一遍：基本資料改個設定按「計算」、今日建議記一餐再撤銷、「自己選」選一樣東西記下來 → 點起來順、按得到、沒有卡住或畫面跑版。
3. 這次改動的地方（實作者列出來）→ 看得懂、跟你想的一樣。有覺得怪、看不懂、不順手的，直接截圖說。

以下第 0–4 節是完整步驟，由自動版負責，使用者不用逐條跑。

## 0. 開啟

1. 用手機開正式網址 https://tongxiaooppo-boop.github.io/Lighten2/ （GitHub Pages，master 根目錄，推送後約 1 分鐘更新）→ 頁面正常顯示，上方分頁只有「基本資料／今日建議／本週總覽／運動紀錄／採買清單」五個（沒有美饗日曆）。
2. 部署新版本後重新打開（不手動清快取）→ 看到的是新版本（import map 版本字串，章程 C1.6）。GitHub Pages 讓首頁暫存最多 10 分鐘（`Cache-Control: max-age=600`），推送後 10 分鐘內可能還是舊版；超過 10 分鐘還是舊版才算問題。辨認方法：「自己選」的品項卡片沒有圖、也沒有色塊的就是新版。

## 1. 基本資料

1. 填年齡、性別、身高、體重、活動量、目標模式，按「計算」→ 計算結果出現；體重趨勢校正卡片顯示「公式目標／校正值／目前每日目標」。
2. 過敏原勾選框、「今日建議時段與來源」下拉都點得到，按鈕高度夠手指點（≥ 44px）。
3. 「今日體重回填」送出 → 顯示「已記錄 日期 體重 kg」。
4. 過敏原勾選框有 10 個（含「軟體動物」「花生」）；飲食型態下拉沒有「低碳」，另有「低碳」勾選框與「家裡用油習慣：一般／少油」下拉；勾選、改選後按「計算」，重新整理再回來，設定還在（−1b）。

## 2. 今日建議

1. 切到今日建議 → 上方彙總卡顯示接下來幾餐的建議熱量；各時段有推薦卡片；關閉的時段顯示「已設定不需要這個時段的建議」。
2. 按「記錄這餐」→ 該時段變成「已記錄：…（約 N kcal）」＋「撤銷」；彙總卡的熱量與蛋白質跟著變。
3. 按「撤銷」→ 該時段回到推薦卡片。
4. 按「倒讚」→ 該時段換一個推薦。
5. 按「順便不要」的晶片 → 該食材/品項從推薦中消失，也出現在基本資料的「不吃的食材」。
6. 記下推薦卡片上的組合，切到別的分頁再切回來 → 推薦跟剛才一樣，沒有整批換掉（−1b，decisions #39）。
7. 按「記錄這餐」記早餐 → 午餐、晚餐的推薦不變，而且不會出現剛才早餐吃的同一個品項。
8. 自煮的推薦卡片（煎、炒）的基準熱量後面有「含用油約 Ng」；基本資料改成「少油」後，數字減半。推薦到溫沙拉時，括號裡還有「未含沙拉醬」。
8a. 每張推薦卡片的圖都是該時段的插畫（早餐、午餐…各一張），不會出現雞胸肉、豆腐這類食材照片（decisions #8）。
9. 彙總卡展開營養明細 → 有「鈉 約 N mg（參考 2400 mg）　飽和脂肪 約 N g」（或「無資料」「部分品項無資料」），沒有顏色或警告。

## 3. 自己選

> 目前還是 v1 的舊選擇器：品項沒有依基本資料的來源分成超商／外食／自煮三頁、便當與整份餐盒不列（台式外食只有飲料）、飲料跟食物在同一頁、自煮沒有用油／調味選項、沒有「我的品項」快速新增。這些都是 Phase 0 的工作（PRD 第 7 節 Phase 0 列），−1b 測試時不算問題。

1. 在推薦卡片按「自己選」→ 彈出視窗，預設「現成品項」，卡片可以捲動、點選；品項卡片只有名稱和熱量，沒有任何圖片（decisions #8）。
2. 選一個主餐 → 下方摘要「已選 1 件 · 約 N kcal … · 鈉 約 N mg」；同一角色選第二個時出現提示。
2a. 早餐只選一杯飲料「拿鐵咖啡（無糖，大杯）」→ 摘要是「鈉 約 113 mg」，不是「無資料」；「記下這餐」可以按，記得下來（手動記錄不要求主餐，−1b；驗收審核 A1）。
2b. 到基本資料勾任一個過敏原（例：蛋）並按「計算」，再開「自己選」→ 超商沙拉（香草烤雞沙拉、海藻沙拉、薯泥蛋沙拉、藜麥沙拉盒）、高蛋白飲、Soyjoy 這類複合料理灰掉並顯示「成分未確認」；沒勾過敏原時不會灰。（「自己選」的現成品項本來就不列便當與整份餐盒、台式外食只列飲料，是 v1 的設計，Phase 0 的超商／外食分頁才會全部列出。）
3. 按「記下這餐」→ 視窗關閉，該時段變成已記錄。
4. 切到「自己煮」→ 依序選餐型、蛋白質、主食、烹調法，份量滑桿可以拖 → 摘要跟著變；按「記下這餐」→ 該時段變成已記錄。
4a. 午餐「自己煮」選「溫沙拉」→ 摘要最後有「未含沙拉醬」；換成其他餐型就沒有（decisions #38）。
5. 早餐「自己煮」選「早餐碗」→ 烹調法有「免開火」「微波」可選，兩個都能選、能送出。（「這個食材需要加熱」的防呆目前手機上觸發不到：有免開火的餐型只有早餐碗，它能選的食材都不需加熱；這條規則由 diff-recs 的 `compose/*/no-cook-unsafe` 情境自動測。）
6. 點視窗外的灰色區域或按「取消」→ 視窗關閉，沒有記錄。

## 4. 本週總覽、運動紀錄

1. 本週總覽 → 列出本週每一天的熱量；沒有完整記錄的日子時顯示說明文字。
2. 運動紀錄 → 選項目、填分鐘、送出 → 歷史紀錄出現；本週活動量文字更新；運動分頁不出現任何飲食熱量。
