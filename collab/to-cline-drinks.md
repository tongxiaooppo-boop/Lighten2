## 每一筆的欄位

```json
{
  "_by": "你的模型名稱",
  "_date": "2026-MM-DD",
  "items": [
    {
      "no": 3,
      "name": "原萃 綠茶（寶特瓶 580ml）",
      "group": "超商",
      "serving_ml": 580,
      "kcal": 0,
      "protein_g": 0,
      "carb_g": 0,
      "fat_g": 0,
      "sat_fat_g": 0,
      "sodium_mg": 10,
      "fiber_g": null,
      "sugar_g": 0,
      "allergen_tags": [],
      "vegan": true,
      "lacto_ovo": true,
      "sources": [
        { "fields": ["kcal", "protein_g", "carb_g", "fat_g", "sat_fat_g", "sodium_mg", "sugar_g"], "type": "包裝標示", "url": "https://…", "checked": "2026-MM-DD" }
      ],
      "confidence": "high",
      "note": "另有 975ml 大瓶裝；營養標示每 100ml 換算成整瓶。"
    }
  ]
}
```

- `no`：上面清單的編號，原樣填。
- `group`：只能是 `超商` 或 `手搖飲・咖啡・早餐店`。包裝飲料（1–19）填 `超商`，店家現做（20–38）填 `手搖飲・咖啡・早餐店`。
- 數字一律是**一份（整瓶或整杯）**的量。包裝只標每 100ml 的，乘以容量換算，在 `note` 寫怎麼換算的。
- 包裝標示沒有的欄位（常見：纖維、飽和脂肪）寫 `null`，不要寫 0。只有標示明寫 0 才寫 0。
- `sugar_g` 是參考用，查得到就填。
- `sources`：**每個數字都要能對到一筆出處**。`type` 只能是：`包裝標示`（照片或電商頁面上的營養標示）、`官網營養標示`、`衛福部`（寫整合編號與樣品名）、`估算`（寫算法，例：「清漿以衛福部 豆漿(無糖) 每 100ml 換算 450ml」）。`checked` 寫你查的日期。
- `confidence`：`high`（官方標示）、`medium`（衛福部樣品或可信的二手資料）、`low`（估算）。

## 過敏原：只能用這 12 個詞

`甲殼類`、`軟體動物`、`魚`、`蛋`、`乳製品`、`花生`、`堅果`、`麩質`、`黃豆`、`芝麻`、`芒果`，以及 `未確認`

- **包裝飲料**：照包裝上的過敏原標示與成分表。含奶精、奶粉、鮮奶、乳清的標 `乳製品`；豆漿標 `黃豆`；麥仔茶、含大麥或燕麥的標 `麩質`。
- **市售調配飲料**（可樂、汽水、非原汁果汁、乳酸飲料）**查不到成分表的，標 `["未確認"]`**。查得到成分表就照成分標。
- **店家現做**：奶茶、鮮奶茶、冰淇淋紅茶、多多綠茶標 `乳製品`；米漿通常含花生，要查清楚，確定的話標 `花生`；配方依店家而異、查不到的加 `未確認`。
- **無糖純茶、黑咖啡、氣泡水（原味）**：只有茶葉或咖啡加水，可以標 `[]`（確認不含）。
- 拿不準一律標 `未確認`，**往保守方向**。這是安全問題：標成「確認不含」但其實有過敏原，會讓過敏的人選到。
- 奶精不一定含乳：查不到時標 `未確認`，不要直接標 `乳製品` 或 `[]`。

## 葷素

- `vegan`（全素）：完全沒有動物成分、而且過敏原不是 `未確認`，才填 `true`。含乳製品、蛋、蜂蜜、明膠的一律 `false`。
- `lacto_ovo`（蛋奶素）：可以有蛋和乳製品，不能有肉、魚、海鮮、明膠。全素的也填 `true`。
- 過敏原含 `未確認` 的，`vegan` 一律 `false`；`lacto_ovo` 除非包裝有素食標示，否則也填 `false`，並在 `note` 寫依據。
- 包裝上有「全素」「蛋奶素」標示的，照標示填，在 `sources` 註明。
