日期：2026-09-29　實作者：Opus（Lighten2 主導開發）　審核者：新開的獨立 Opus agent

## 背景（對話摘要）

Phase 0 完成後，使用者問：食材或原有組合能不能單獨查詢營養成分、熱量、能在哪些餐出現，以及怎麼增減與修訂，PRD 有沒有規範。實作者回報：只有超商／外食品項的「隱藏＋複製成我的版本」（PRD 10.2）與我的品項管理（B-1）、我的組合管理（11.5，內容不能直接編輯）有規範；單獨查詢、食材與骨架的增修都沒有。

使用者補充：「不只是可以增加食材，而是可以修訂。當然衛福部那類的基礎食材營養成分無法修改，能改的是自己組合＋便利／外食餐點內容及營養成分。」

實作者建議（使用者回「照你的建議」）：
1. 三層資料：基礎食材與內建資料只能查；使用者自己的資料能改；數字標出處。
2. 「食物資料」查詢頁（含衛福部全表），併進 B-1。
3. 內建餐點維持複製後再改，外加份量倍數。
4. 新增我的食材（從衛福部加入或自填）與我的料理（不綁骨架、只用在手動記錄、不進推薦）。
5. 我的組合改成可以直接編輯。
6. 順序：B-3 匯出匯入 → B-1（擴大）→ B-4 我的食材與料理。

PRD 第 12 節草案、0.1 第 12 點、6.3 例外、10.6、11.5、第 7 節路線圖已改；decisions #50–#55 已記。

**N2【一定要改】常買清單用 import 白名單擋不住**（C4.17；`js/ui/meal-picker/index.js` L8 直接 import 共用的 `getSetting`、`setSetting`）

**N3【一定要改】`oil_g`、`seasoning` 和 `servings` 的語意矛盾，會默默算錯**（12.5 L530–532、L541）

- L530 寫 `oil_g` 是「這份食譜總共的用油」，預設卻是固定 5g。做 4 份的話，每份只有 1.25g。
- 要寫定兩件事：
  - 調味是「每份」加（總鈉＝每份鈉 × `servings`），或者 L541 改成「食材與用油加總後除以份數，再加每份的調味」；
  - 用油預設＝5g × `servings` × 用油習慣，或者把 `oil_g` 改成「每份用油」。

**N4【一定要改】料理的用油與調味跟章程 B5.6、B5.7、decisions #42 的關係沒寫進章程**
- B5.6 的預設用油由烹調法決定，「自己選」只能從預設、1 茶匙、2 茶匙裡選。料理的 `oil_g` 是自由填的數字，包括 0（L530，B8 寫 `oil_g ≥ 0`）。
- #42 的立場是：「不用油」如果做成一鍵選項，會重新打開低估的問題，所以要跟「不加調味」同一批送 C3。現在料理可以直接填 0g 油，調味卻不能選「不加」（L531 仍掛在待 C3）。這個不對稱要寫出理由，例如「料理是使用者自己寫的整份食譜，跟克數一樣是使用者輸入」。或者兩者一起處理。

- 12.7 與 CHARTER 要補兩條加註：
  - B5.6：料理的用油是使用者輸入，預設 5g 的出處是 `assumption`；

**N6【建議】`recipe` 元件跟現有程式的銜接**

  4. 11.3 規則 4 寫「`archetype_id` 已不存在 → 自煮元件被擋」。料理那一餐的 `archetype_id` 是 null，要寫明這時略過規則 4。

**N7【一定要改】`filled` 的驗證與衛福部改版、匯入**（12.4 L500、CHARTER B8、L253）
