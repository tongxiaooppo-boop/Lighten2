#### 1.4 預設分頁的完整規則
```
modal 預設型態 =
    plan[date|slot].meal_type          // Phase 2 才有；Phase 0 固定是 null
 ?? (isMealType(meal_prefs[slot]) ? meal_prefs[slot] : null)
 ?? (isMealType(lastPicked[slot])  ? lastPicked[slot]  : null)
 ?? "convenience"                      // fallback

推薦引擎的有效型態（Phase 2）= plan ?? meal_prefs   ← 永遠不含 lastPicked
```
isMealType(v) 指 v 屬於那 4 個型態值，"auto"、"off"、undefined 都當「沒有值」。fallback 改成超商的理由：DEFAULT_MEAL_PREFS 裡會是 auto 的只有下午茶和宵夜，自煮在這兩個時段選項很少（bowl_oat / egg_pan），停在自煮分頁畫面會很空。型態對應分頁：convenience→超商、delivery→外食、cook_quick→自煮(快煮)、cook_full→自煮(開伙)。Phase 0 寫成 resolveDefaultMealType({ planned, pref, lastPicked })，planned 先傳 null，Phase 2 只改呼叫端。

#### 1.5 會不會變成第三層？
只要守住三條規則就不會。只影響 modal 打開時停在哪一頁，不影響推薦、預算、任何統計數字。程式碼註解要寫明：「推薦引擎、統計、主畫面（hero）不得讀取 picker_last_meal_type」。驗收時 grep 確認這個 key 只出現在 tab-today.js 的 modal 區段。

已知的副作用（刻意接受）：使用者設 auto 但每次都選超商，modal 會一直停在超商，今日推薦卡片卻照樣混著推自煮。不要讓引擎讀 lastPicked 來「修正」這一點，也不要跳出「要不要把午餐設成超商？」這類提示。

### 4. 核心原則風險盤點（這次定案新增部分）

**不評判超吃**
- lastPicked 只覆蓋、不計數、不存時間、不顯示、沒有邏輯讀它，守住就累積不出行為輪廓。
- daily_log.meal_type 是新的高風險欄位：有了它就能統計「這週外食 5 次」。規則：任何 UI 不得依 meal_type 做頻率統計並搭配評價性文字或顏色，不得出現「外食比較多喔」「多自己煮吧」。只能用在解析規則、採買清單、中性顯示（例如圖示）。這條要寫進 PRD 原則章節。
- 商品排序禁止依熱量排序，不用紅綠色區分。飲料步驟不做糖量警告、不預設無糖。
- Phase 2 以後：實際吃的跟計畫不一樣，L3 默默蓋過 L2，不出現「你沒照計畫吃」「計畫達成率」。

**運動和飲食脫鉤**
- modal 的配額計算不可加入運動消耗。meal_type/lastPicked 都不讀 exercise_log。不做「今天有運動，預設停在高蛋白自煮」之類聯動。

### 5. 地雷與矛盾

1. Phase 0 跟使用者幾小時前的決定方向相反（b535443 是整個拿掉現成品項）。判斷這是合理的，因為使用者當時不滿的是「飲料洗版」跟「跟美饗日曆功能重複」兩件事，新設計都解決了：飲料抽到獨立步驟；「自己選」負責記錄實際吃了什麼（L3），日曆負責規劃（L2），共用同一個選擇器是刻意重用不是重複做一套。但要明確讓使用者知道，避免他覺得「我不是叫你刪掉了嗎」。
2. lastPicked 和 auto 語意上會有落差：modal「記得」使用者偏好超商，推薦卡片卻不管這件事。這是守住 L1/L2 權威性必須付出的代價，PRD 要寫明「刻意不同步」。
3. 「複製上週」有兩個雷（Phase 2）：大餐/商品計畫會預先佔用預算，一起複製會讓一次性大餐每週自動重複佔用預算——規則：預設不複製 is_feast 項目，已有計畫的日期/時段預設跳過不覆蓋，只複製到今天以後的日期。使用者可能期待「複製上週實際吃的」，但 MVP 只從計畫複製，不從 L3 紀錄複製（否則紀錄變成偏好來源），空的時候顯示「上週沒有排計畫」並提供「用今天的偏好預填」選項（來源是 L1）。
4. 人口數（情境 A）存放位置：meal_plan entry 加 servings（預設值來自新的 L1 欄位 profile.household_size，預設 1）。daily_log 只記使用者自己那一份。採買清單的量＝名目份量 × servings（使用者自己那份也用名目份量，不乘當天縮放倍數），標「估算」。
5. 列舉有一個舊值 "off"：解析規則一律把非型態值當「沒有值」。時段被停用時 modal 本來就不該打得開，請 Cline 順手確認。
6. Phase 0 範圍比 b535443 大約一倍，建議分兩輪交辦給 Cline。
